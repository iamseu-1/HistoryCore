# P2-3 색인 여덟 · 증분 색인 · 100만 편에서 9-2 통과 — 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **가벼운 계획**(memory `workflow-autonomy`, 2026-10-22). 이 계획은 인터페이스 · 먼저 쓸 검사 · 까다로운 곳만 적는다. 구현은 실행하면서 쓴다. 검사 이름과 입력 → 기대는 약속이고, 검사 코드는 실행자가 그 약속대로 먼저 쓴다(빨간불을 본 뒤 구현).

**Goal:** 설계 5-5의 색인 여덟과 저장해 둔 그리기 모델을 파생 파일 `index.db`에 두고, 바뀐 문서만 따라잡는다. 여기에 다리 op와 Dart API를 붙이고, PC에서 100만 편으로 9-2 예산표를 통과한다(P2의 통과 기준).

**Architecture:**
- 새 상자 `crates/index`(`history_index`)가 `Engine { lib: Library, idx: Index }`를 갖는다. 다리와 측정기는 `Library` 대신 `Engine`을 쓴다.
- 저장은 `library.db`에 먼저 커밋하고, 이어서 같은 호출 안에서 그 문서의 색인 · 모델을 `index.db`에 커밋한다.
- 색인은 `rev.seq`(INTEGER PRIMARY KEY, 늘기만 함) 눈금과 `stale` 대기표로 어디까지 했는지 안다. 끊긴 저장 · 동기화로 들어온 판 · 바뀐 틀은 `index.step`이 뒤에서 조금씩 따라잡는다. **시작할 때 통째로 다시 짓지 않는다.**
- 검색은 Rust가 한글 · 한자를 2글자 조각으로 잘라 넣는 contentless FTS5(`detail=none`)다. 3글자 넘는 검색어는 조각 AND로 후보를 얻고, 저장해 둔 글자로 확인한다.
- 통째 짓기(측정기 · 새 기기)는 따로 된 빠른 길이다: 여러 스레드가 해석 · 조각내기를 하고 쓰는 스레드 하나가 `index.db.building`에 쓴 뒤 바꿔 끼운다.

**Tech Stack:** Rust 1.94.1 · rusqlite 0.37(bundled, FTS5) · zstd · serde_json(`raw_value`) · std 스레드(새 무거운 의존 없음) · Flutter 플러그인 `packages/history_core`

**Spec:** `docs/superpowers/specs/2026-10-21-remake-ecosystem-design.md` — 5-1 · 5-3 · 5-5 · 5-6 · 5-7 · 8-2 · 9-1 · 9-2 · 9-3

## Review Focus

1. **색인만 낡은 문서.** 서재 커밋 뒤 색인 커밋 전에 끊기거나, 동기화로 판만 들어온 경우다. 다시 열면 `index.status`가 그 문서를 낡음으로 세고, `doc.open`은 그 자리에서 머리 판으로 그려 준다. 옛 모델을 지금 것처럼 보이지 않는다. → Task 3 · 4 검사
2. **분류 나무가 꼬일 때.** 고리(가 → 나 → 가) · 분류 문서가 없는 분류 · 집 분류가 바뀐 문서 · 부모가 바뀐 분류 문서 · 지운 문서가 섞인다. 그래도 맨 위 폴더 수의 합 + 「분류 안 됨」 = 살아 있는 일반 문서 수가 늘 맞고, 고리는 끊고 경고한다. → Task 5 무작위 검사

### Task 2: 검색 조각 · 질의 · 100만 편 측정 (먼저 재 본다)

이 계획에서 제일 위험한 곳이라 먼저 한다. P1의 trigram은 본문 찾기 p95 32ms, 들이기 44분 중 대부분이 FTS 짓기였다.

**Files:** Create `crates/index/{Cargo.toml, src/lib.rs, src/search.rs}` · `crates/index/tests/search.rs`. Modify 작업공간 `Cargo.toml` members · `crates/bench/src/main.rs`(하위 명령 `search`)

**Interfaces — Produces(`history_index::search`):**
- `fn index_tokens(text: &str) -> Vec<String>` — 넣을 조각. 겹침이 없는 차례(문서 안 같은 조각은 한 번).
- `struct Query { pub must: Vec<String>, pub prefix: Option<String>, pub verify: Vec<String> }` · `fn parse_query(q: &str) -> Option<Query>`(조각이 하나도 없으면 None)
- `fn fts_match(q: &Query) -> String` — FTS5 MATCH 글
- `fn verify(plain: &str, q: &Query) -> bool` · `fn snippet(plain: &str, q: &Query, around: usize) -> String`
- `fn normalize(text: &str) -> String` — NFC + 소문자. 넣을 때와 찾을 때 같은 것을 쓴다.
- FTS 표: `CREATE VIRTUAL TABLE fts USING fts5(t, content='', contentless_delete=1, detail=none, tokenize='ascii')` — rowid는 색인의 문서 번호다.

**조각 규칙:**
- 「덩이 글자」는 한글 음절 U+AC00–D7A3과 한자(`model.rs`의 `is_han`과 같은 범위)다.
- 덩이 글자가 이어진 한 덩이 `c1…cn`은 겹치는 2글자 `c1c2, c2c3, …`과 끝 글자 하나 `cn`을 낸다. n=1이면 `c1`만 낸다.
- 그 밖의 글자: 영문 · 숫자 등 단어 글자(`char::is_alphanumeric`)가 이어지면 소문자 단어 하나다. 나머지(공백 · 구두점 · 이모지)는 가른다.
- 질의:
  - 덩이 길이 ≥ 2 → 그 2글자들을 `must`에, 덩이 전체를 `verify`에 넣는다.
  - 덩이 길이 1 → `prefix`로 `c*`. 1글자 질의는 예산 밖이고 되기만 하면 된다.
  - 단어 → `must`.
  - 2글자 덩이 하나뿐인 질의는 `verify`가 비어도 된다(조각이 곧 그 글자다).

**먼저 쓸 검사(`tests/search.rs`):**
- `tokens_of_hangul_runs` — `"임진왜란"` → `["임진","진왜","왜란","란"]`(차례 무관 비교 시 집합으로)
- `tokens_mix_scripts` — `"鶴𪄃 Joseon 1592년"` → `{"鶴𪄃","𪄃","joseon","1592","년"}`. 𪄃은 is_han 범위 안이고, `1592년`은 단어 `1592` + 덩이 `년`이다.
- `nfd_hangul_is_found` — 결합 자모로 친 `"임진"`(U+1109…)이 `normalize` 뒤 같은 조각을 낸다
- `query_shapes` — `"임진왜란"` → must 3개 · verify `["임진왜란"]`. `"왜란 조선"` → must `["왜란","조선"]`. `"鶴"` → prefix `"鶴*"`. `"   "` → None
